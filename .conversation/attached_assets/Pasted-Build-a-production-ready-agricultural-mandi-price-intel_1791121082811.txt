Build a **production-ready agricultural mandi price intelligence web application** that can later be packaged as an Android APK.

The application is intended for **real farmers, traders, and agricultural users**, so the UI must be extremely simple, trustworthy, mobile-first, and understandable to a person with basic smartphone knowledge.

Do NOT make it look like an AI demo, developer dashboard, or college prototype. It should look like a real-world Indian agricultural market application.

## 1. Core purpose

The application should help a farmer/user answer three simple questions:

1. **What is today's mandi price?**
2. **What is the expected price over the next 7 days?**
3. **Should I HOLD my commodity or RELEASE/SELL it now?**

The application should present complex market data in very simple language.

---

# 2. USER TYPES

Implement three access levels:

### A. Guest User

A guest user should be able to:

* Open the application without creating an account.
* Select Commodity.
* Select State.
* Select Mandi.
* Select Variety if available.
* View today's market information.
* View the 7-day price forecast.
* View the Hold / Release recommendation.

Guest users should have limited functionality but should NOT be forced to register just to see basic market information.

Provide a clear option:

**Login / Register**

---

### B. Authenticated User

Users should authenticate using their **phone number**.

Authentication flow:

1. Enter mobile number.
2. Send OTP.
3. Verify OTP.
4. Create/login to account.
5. Store basic user profile.

Do not ask for unnecessary personal information.

After login, allow users to:

* Save preferred commodity.
* Save preferred mandi.
* View market information.
* View forecasts.
* View Hold / Release recommendations.
* See their recently selected markets.

Design authentication for Indian users and use:

**+91**

---

### C. Admin

Create a separate Admin dashboard.

Admin should be able to:

* Login securely.
* Manage commodities.
* Manage states.
* Manage mandis.
* Manage varieties.
* Manage market prices.
* Manage arrivals.
* Manage historical market data.
* Manage forecast data/model status.
* View registered users.
* Manage/update market datasets.
* See data freshness / last updated time.
* Enable/disable commodities or mandis.

Admin dashboard should be separate from the normal user interface.

# 8. HOLD OR RELEASE FEATURE

This is one of the most important features.

Create a prominent section:

# Should You Hold or Sell?

The application should analyze today's price against the predicted price over the next 7 days.

Possible recommendation states:

### HOLD

Example:

**HOLD**

"Prices are expected to increase over the next 7 days."

"Expected price: ₹2,250/qtl"

"Current price: ₹2,000/qtl"

"Potential increase: ₹250/qtl"

---

### RELEASE / SELL

Example:

**RELEASE / SELL**

"Prices are not expected to increase significantly over the next 7 days."

"Current price: ₹2,000/qtl"

"Expected price: ₹1,920/qtl"

---

### WAIT / UNCERTAIN

If the forecast is too uncertain:

**WAIT / CHECK AGAIN**

"Price movement is uncertain. We don't have enough confidence to recommend holding or selling."

This is important because the application should NOT force a Hold/Sell decision when the prediction is unreliable.

* Current modal price
* 7-day predicted prices
* Historical trend
* Forecast confidence
* Optional market volatility

Output:

* HOLD
* RELEASE
* WAIT / UNCERTAIN

Also return a human-readable explanation.

Example:

{
"recommendation": "HOLD",
"currentPrice": 2000,
"forecastPrice": 2250,
"expectedChange": 12.5,
"reason": "Prices are expected to increase over the next 7 days."
